## Requirements
### Requirement: Full 26-leaf pod catalog parity across Rust and Python

`HierarchicalFleetManager._build_rust_pods_for_leaf` (`backend/core/hierarchy.py`) and `ecosystem_pod_specs(leaf_id)` (`engine-rs/crates/strategies/src/lib.rs`) MUST produce an identical Strategy Pod catalog for every leaf identifier among all 26 supported ecosystems (`leaf-solana`, `leaf-bitcoin`, `leaf-ethereum`, `leaf-bnb`, `leaf-xrp`, `leaf-ton`, `leaf-tron`, `leaf-cardano`, `leaf-avalanche`, `leaf-polkadot`, `leaf-chainlink`, `leaf-sui`, `leaf-near`, `leaf-aptos`, `leaf-cosmos`, `leaf-stacks`, `leaf-dogecoin`, `leaf-icp`, `leaf-canton`, `leaf-celo`, `leaf-tezos`, `leaf-flow`, `leaf-eos`, `leaf-hyperliquid`, `leaf-binance-cex`, `leaf-paper-sandbox`).
Each pod entry in the catalog MUST contain identical values across the following fields:
- `slot_id`: a valid canonical slot identifier matching `pod_carry`, `pod_momentum`, `pod_onchain_alpha`, or `pod_sniper`.
- `pod_code`: a unique snake_case strategy code string.
- `name`: a descriptive display name string.
- `archetype`: a standardized uppercase strategy archetype identifier string.
- `native_venue`: the primary execution venue or protocol string.
- `default_weight`: the assigned initial allocation weight float between `0.0` and `1.0`.
- `description`: a French or English description string detailing strategy logic.

The number of strategy pods per leaf MUST satisfy `1 <= count <= 4`. The 7 diverging leaves identified in the architecture audit (`leaf-bnb`, `leaf-xrp`, `leaf-ton`, `leaf-tron`, `leaf-avalanche`, `leaf-cosmos`, `leaf-binance-cex`) and all fallback ecosystems MUST match their Rust definitions with 100% attribute equality.

#### Scenario: All 26 leaves exhibit identical pod definitions in Python and Rust
- **WHEN** the pod catalogs for all 26 leaf identifiers are generated by Python and exported from Rust
- **THEN** every leaf contains between 1 and 4 strategy pods
- **THEN** every pod entry matches in `slot_id`, `pod_code`, `name`, `archetype`, `native_venue`, `default_weight`, and `description`

#### Scenario: Divergent audit leaves match Rust canonical specs
- **WHEN** the pod catalog for `leaf-bnb` is inspected in Python
- **THEN** its pods are `bnb_venus_carry`, `bnb_pancake_v3_momentum`, and `bnb_launchpool_whale_flow`
- **THEN** none of its pods are named `bnb_staking_yield_carry` or `bnb_dex_obi_momentum`

#### Scenario: Pod default weights form a valid allocation
- **WHEN** the default weights of any leaf catalog are summed
- **THEN** each individual weight is strictly greater than `0.0`
- **THEN** the sum of default weights for that leaf is less than or equal to `1.0`

### Requirement: Node CLI exports deterministic pod catalog

`robotrader-node` CLI MUST provide a command-line flag `--dump-pod-catalog` (with alias `--export-pod-catalog`) that serializes and prints the Rust Strategy Pod catalog to standard output as deterministic JSON. When invoked without `--leaf-id`, the output MUST be a JSON object mapping each of the 26 leaf identifiers to its list of `EcosystemPodSpec` objects. When invoked with `--leaf-id <id>`, the output MUST be a JSON array of the pod catalog for that specific leaf. The CLI MUST exit with code 0 on successful export and write no non-JSON text to standard output. When `--leaf-id` is provided with an unrecognized leaf identifier (not belonging to the 26 supported leaf identifiers), `robotrader-node` MUST exit with a non-zero exit code and emit an error message on stderr, and MUST NOT emit a catalog array on stdout.

#### Scenario: CLI exports full fleet pod catalog as valid JSON
- **WHEN** `robotrader-node --dump-pod-catalog` is executed
- **THEN** the process exits with status code 0
- **THEN** standard output parses as a JSON object containing exactly 26 leaf keys
- **THEN** each key contains a list of 1 to 4 serialized pod specifications

#### Scenario: CLI exports single leaf pod catalog
- **WHEN** `robotrader-node --dump-pod-catalog --leaf-id leaf-solana` is executed
- **THEN** the process exits with status code 0
- **THEN** standard output parses as a JSON list containing the 4 Solana strategy pod specifications

#### Scenario: CLI rejects unrecognized leaf identifier
- **WHEN** `robotrader-node --dump-pod-catalog --leaf-id leaf-unknown` is executed with an unrecognized leaf identifier
- **THEN** the process exits with a non-zero status code
- **THEN** an error message is printed to stderr stating that the leaf identifier is unrecognized
- **THEN** stdout does not emit a successful catalog payload

### Requirement: Automated parity verification gate

An automated test suite MUST verify 100% parity between Python `HierarchicalFleetManager._build_rust_pods_for_leaf` and Rust `ecosystem_pod_specs`. The test MUST execute against all 26 leaf identifiers and assert exact string and numeric equality across all pod attributes. Any discrepancy in count, naming, slot, archetype, venue, weight, or description SHALL fail the test build.

#### Scenario: Automated test asserts full fleet catalog parity
- **WHEN** the catalog parity test suite runs
- **THEN** all 26 leaf comparisons pass with zero discrepancies
- **THEN** the test suite exits with success

#### Scenario: Discrepancy in any attribute triggers test failure
- **WHEN** a pod attribute such as `name` or `default_weight` differs between Python and Rust
- **THEN** the parity test fails and reports the exact leaf identifier and mismatching key
