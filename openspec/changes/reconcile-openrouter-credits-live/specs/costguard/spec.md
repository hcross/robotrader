# costguard Delta Specification

## ADDED Requirements

### Requirement: Live OpenRouter credit balance probe and fallback

`LLMMonitorAgent` MUST implement a `reconcile_openrouter_credits(self, timeout_sec: float = 3.0) -> Dict[str, Any]` method that queries `GET https://openrouter.ai/api/v1/credits` with an `Authorization: Bearer <OPENROUTER_API_KEY>` HTTP header when `OPENROUTER_API_KEY` is present, non-empty, and not a known placeholder (`"your_..."` or `"sk-or-v1-placeholder"`). When the HTTP probe returns status 200 OK with valid JSON containing finite numbers for `data.total_credits` and `data.total_usage`, `openrouter_balance_usd` MUST be updated to `round(max(0.0, total_credits - total_usage), 4)`, `balance_source` MUST transition to `"MEASURED_OPENROUTER_API"`, and `last_reconciled_ms` MUST record the evaluation timestamp. When `OPENROUTER_API_KEY` is unset, empty, or a placeholder, or when the HTTP request fails, times out, returns a non-200 status, or returns malformed or non-finite JSON, `reconcile_openrouter_credits` MUST NOT raise an unhandled exception; it MUST preserve the existing `openrouter_balance_usd`, maintain `balance_source` as `"SIMULATED_INTERNAL_LEDGER"` (unless a prior live reconciliation succeeded, in which case `openrouter_balance_usd` is preserved), and return a structured diagnostic dict with `reconciliation_status: "FALLBACK_SIMULATED"` and the failure reason.

#### Scenario: Successful live API probe updates credit balance and provenance
- **WHEN** `OPENROUTER_API_KEY` is configured and `GET https://openrouter.ai/api/v1/credits` responds with HTTP 200 and `{"data": {"total_credits": 15.50, "total_usage": 5.25}}`
- **THEN** `openrouter_balance_usd` is updated to `10.25`
- **THEN** `balance_source` transitions to `"MEASURED_OPENROUTER_API"` and `last_reconciled_ms` is recorded

#### Scenario: Unset or placeholder API key bypasses network probe and reports fallback
- **WHEN** `OPENROUTER_API_KEY` is empty, unset, or set to `"your_openrouter_api_key_here"`
- **THEN** `reconcile_openrouter_credits` executes no external network request
- **THEN** `openrouter_balance_usd` is unchanged and the response reports status `"FALLBACK_SIMULATED"`

#### Scenario: Upstream HTTP error or timeout preserves balance and returns fallback status
- **WHEN** the live probe times out after 3.0 seconds or the server responds with HTTP 502 Bad Gateway
- **THEN** `reconcile_openrouter_credits` handles the error without raising an exception
- **THEN** `openrouter_balance_usd` remains unchanged and the response reports status `"FALLBACK_SIMULATED"`

#### Scenario: Malformed or non-finite JSON payload fails safe without mutating balance
- **WHEN** the API returns HTTP 200 with malformed JSON or `{"data": {"total_credits": "NaN", "total_usage": 0.0}}`
- **THEN** `openrouter_balance_usd` is not modified
- **THEN** the response reports status `"FALLBACK_SIMULATED"` with a description of the validation failure

### Requirement: On-demand reconciliation endpoint in control plane

The control-plane application in `backend/server.py` MUST expose an HTTP `POST /api/v1/openrouter/reconcile` endpoint that triggers `LLMMonitorAgent.reconcile_openrouter_credits()`. The endpoint MUST return HTTP 200 containing the structured reconciliation result dictionary with `openrouter_balance_usd`, `balance_source`, `reconciliation_status`, and `timestamp_ms`. When `ROBOTRADER_API_TOKEN` is configured in the environment, the endpoint MUST enforce bearer token authentication.

#### Scenario: Operator invokes on-demand reconciliation endpoint successfully
- **WHEN** an operator sends a valid POST request to `/api/v1/openrouter/reconcile` while upstream OpenRouter returns valid credit metrics
- **THEN** the endpoint returns HTTP 200 with `balance_source = "MEASURED_OPENROUTER_API"` and the reconciled balance

#### Scenario: Upstream failure during on-demand reconciliation returns structured fallback without server error
- **WHEN** an operator sends a POST request to `/api/v1/openrouter/reconcile` while OpenRouter is unreachable
- **THEN** the endpoint returns HTTP 200 with `reconciliation_status = "FALLBACK_SIMULATED"` and the preserved balance

### Requirement: Out-of-band settlement metadata on approved refills

Every approved refill event generated by `LLMMonitorAgent.trigger_openrouter_refill` MUST record explicit settlement metadata in both the return dictionary and the recorded `refill_history` entry. When `balance_source` is `"MEASURED_OPENROUTER_API"`, `settlement_mode` MUST be set to `"OPERATOR_OUT_OF_BAND_INTENT"`, indicating that programmatic payment execution is not supported by OpenRouter and requires manual out-of-band operator funding. When `balance_source` is `"SIMULATED_INTERNAL_LEDGER"`, `settlement_mode` MUST be set to `"SIMULATED_LEDGER_INCREMENT"`. In addition, every approved refill MUST include a deterministic and unique `settlement_receipt_id` formatted as `f"or-refill-{now_ms}-{len(self.refill_history) + 1}"`.

#### Scenario: Refill under measured provenance records out-of-band operator intent settlement
- **WHEN** `balance_source` is `"MEASURED_OPENROUTER_API"` and a refill is approved by `HardRiskGate`
- **THEN** the resulting refill event records `"settlement_mode": "OPERATOR_OUT_OF_BAND_INTENT"`
- **THEN** the resulting refill event records a `"settlement_receipt_id"` starting with `"or-refill-"`

#### Scenario: Refill under simulated provenance records simulated ledger increment settlement
- **WHEN** `balance_source` is `"SIMULATED_INTERNAL_LEDGER"` and a refill is approved by `HardRiskGate`
- **THEN** the resulting refill event records `"settlement_mode": "SIMULATED_LEDGER_INCREMENT"`
- **THEN** the resulting refill event records a `"settlement_receipt_id"` starting with `"or-refill-"`

#### Scenario: Consecutive approved refills receive unique and incrementing receipt identifiers
- **WHEN** two consecutive refills are approved at timestamps `1700000001000` and `1700000002000`
- **THEN** the first event has `"settlement_receipt_id": "or-refill-1700000001000-1"`
- **THEN** the second event has `"settlement_receipt_id": "or-refill-1700000002000-2"`
